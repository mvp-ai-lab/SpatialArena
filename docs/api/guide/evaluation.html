API Guide / Evaluation API

Evaluation API

Evaluation code in spatialarena/eval reads standardized benchmark datasets and standardized method outputs. It validates artifacts, resolves result paths, computes depth and pose metrics, and writes JSON reports that the data manager can visualize.

Evaluation Flow

  1. Select scenes. The dataset registry chooses benchmark task/dataset specs and materializes BenchmarkSceneInfo records.
  2. Resolve outputs. Result-layout helpers map experiment, task, dataset, method, and scene names to the expected output directory.
  3. Validate artifacts. Prediction validators check for depth files, sparse COLMAP models, point clouds, or metrics files.
  4. Run task evaluator. Depth, sparse pose (SfM), SLAM trajectory, mesh, or ScanNet++ evaluators load GT/predictions and compute scene-level metrics.
  5. Aggregate reports. Evaluators return per-scene results, errors, and aggregate metrics suitable for JSON files and dashboard ingestion.

Benchmark Evaluation Datasets

Evaluation datasets are registered in spatialarena/eval/dataset_registry.py. They are canonical benchmark folders, not FoundationModels training WebDataset roots. The default root is $SPATIALARENA_ROOT/benchmarks; every dataset below is addressed by a task key, dataset key, and root-relative path.

Canonical Evaluation Input Record

Source: spatialarena/eval/canonical_dataset.py

Registry adapters do not pass raw dataset roots directly to evaluators. They first materialize one BenchmarkSceneInfo per evaluated scene. The fields below are the actual evaluator inputs. 

BenchmarkSceneInfo(
  dataset="...",             # dataset key in reports
  task="...",                # MonoDepth, VideoDepth, MVRecon, SfM, SLAM (CameraPose = SfM alias)
  scene="...",               # scene/subset/sequence name
  root_path=...,             # canonical scene root
  image_path=...,            # directory of evaluation RGB frames, when required
  depth_gt_path=...,         # directory of GT depth maps, for depth metrics
  mask_path=...,             # optional valid-pixel masks
  sparse_gt_path=...,        # GT COLMAP model, for pose metrics
  metadata={...},            # metadata.json scene entry
)
  • Depth evaluators: require image_path for scene context and depth_gt_path for GT depth pairing; mask_path is applied when present.
  • Sparse pose evaluators: require image_path and sparse_gt_path; method predictions are read from the method output sparse/0.
  • Geometry evaluators: use dataset-specific mesh, point-cloud, mask, and transform sidecars in addition to the canonical scene record.

Marigold Monocular Depth

Official: Marigold | Spec: MonoDepth / marigold, root MonoDepth/marigold, adapter DatasetMarigold

Marigold packages standard monocular-depth test subsets behind a common tar-backed layout. The evaluator uses a single RGB frame and one GT depth map per example, with optional masks when the materialized subset provides them. The suite uses the AMB3R mono-depth protocol: Marigold subsets are scale-and-shift aligned before depth metrics are computed. 

$BENCHMARK_ROOT/MonoDepth/marigold/
  metadata.json
  <subset>/
    images/                  # image_path
    depths/                  # depth_gt_path
    masks/                   # mask_path, optional
  • root_path: $BENCHMARK_ROOT/MonoDepth/marigold/<subset>.
  • image_path: root_path/images; raw subset names must be canonicalized or symlinked here before evaluation.
  • depth_gt_path: root_path/depths; paired to prediction depth files by normalized frame key.
  • mask_path: root_path/masks when available.
  • sparse_gt_path: not used for MonoDepth.
  • Required artifacts: canonical images, GT depths, optional masks, and metadata.json.
  • Preparation: scripts/download/marigold.sh, then scripts/preprocess/materialize_marigold_sample.py --scenes nyuv2 kitti eth3d diode scannet --max_samples -1 (every image of each subset, 3,331 in total; materializing one subset adds it to the existing metadata.json).
  • Access/license: follow the upstream Marigold and underlying subset terms. Our Hugging Face release ships nyuv2, kitti, eth3d and diode only: ScanNet's terms forbid redistribution, so scannet is rebuilt from Marigold's own download as its LICENSE_NOTICE.md describes. See spatialarena/dataset_licenses.py.

MonoDepth Extension Datasets (AerialMetric, HAMMER, iBims-1, Spring, Synth4K)

Spec: MonoDepth / aerialmetric, hammer, ibims1, spring, synth4k, root MonoDepth/<dataset>, adapters in monodepth_datasets.py

Five MonoDepth datasets in one canonical layout, evaluated with the same standard protocol as Marigold (per-image least-squares scale+shift). Each scene's depth limits live in metadata.json (min_depth, max_depth, depth_scale) and are read by resolve_depth_config; per-frame pixel intrinsics, masks and source ids live in materialized_full.json. 

$BENCHMARK_ROOT/MonoDepth/<dataset>/
  metadata.json              # scenes + depth limits
  <scene>/
    images/                  # image_path
    depths/                  # depth_gt_path, float32 .npy metres, 0 = invalid
    masks/                   # mask_path, optional, 255 = evaluate
    materialized_full.json   # per-frame records
  • Scenes: hammer, ibims1, spring (one each, MoGe's processed eval sets); synth4k (one per game, half of each game's scorable frames: 1,960 in total); aerialmetric (decoupled, oblique, wild, half of each site's scorable frames: 3,596 in total). Every image of a scene is scored.
  • Preparation: scripts/download/{moge_eval,synth4k,aerialmetric}.sh, then scripts/preprocess/materialize_{moge_eval,synth4k,aerialmetric}.py; scripts/preprocess/check_monodepth_gt.py checks the result.
  • Access/license: HAMMER MIT, iBims-1 and Spring CC BY 4.0; AerialMetric academic use only (Wild frames unconfirmed); Synth4K unconfirmed (game imagery). See spatialarena/dataset_licenses.py.

MPI Sintel Video Depth

Official: MPI Sintel | Spec: VideoDepth / sintel, root VideoDepth/sintel, adapter DatasetSintel

Sintel is a synthetic movie-style video benchmark with dense per-frame depth. It is useful for testing temporal depth prediction because each scene is a rendered sequence with known camera motion and dense geometry. GT depths are loaded from Sintel .dpt files; invalid sentinel depths are masked before scoring. 

$BENCHMARK_ROOT/VideoDepth/sintel/
  metadata.json
  <scene>/
    images/                  # image_path
    depths/                  # depth_gt_path, Sintel .dpt files
    masks/                   # mask_path, optional
  • root_path: $BENCHMARK_ROOT/VideoDepth/sintel/<scene>.
  • image_path: root_path/images; sequence frames used for prediction/export.
  • depth_gt_path: root_path/depths; loaded with Sintel .dpt support.
  • mask_path: root_path/masks if materialized; otherwise invalid Sintel sentinels are filtered by the depth loader.
  • sparse_gt_path: not used for VideoDepth.
  • Required artifacts: RGB frames, .dpt GT depth maps, and metadata for scene enumeration.
  • Preparation: scripts/download/sintel.sh.
  • Access/license: follow the MPI Sintel dataset license.

Bonn RGB-D Dynamic Sequences

Official: Bonn RGB-D Dynamic Dataset | Spec: VideoDepth / bonn, root VideoDepth/bonn, adapter DatasetBonn

Bonn contains real RGB-D videos of dynamic indoor scenes. The adapter keeps RGB and depth sequences in canonical scene records and supports timestamp-aware depth pairing, so methods can write predictions by frame name while the evaluator still handles small RGB-D timestamp offsets. 

$BENCHMARK_ROOT/VideoDepth/bonn/
  metadata.json
  <sequence>/
    images/                  # image_path
    depths/                  # depth_gt_path, millimeter-encoded GT depth
    masks/                   # mask_path, optional
  • root_path: $BENCHMARK_ROOT/VideoDepth/bonn/<sequence>.
  • image_path: root_path/images; timestamped RGB inputs should be canonicalized here.
  • depth_gt_path: root_path/depths; evaluator applies the Bonn millimeter-to-meter scale.
  • mask_path: root_path/masks when available.
  • sparse_gt_path: not used for VideoDepth.
  • Required artifacts: RGB sequence, metric depth sequence encoded in millimeters, optional masks, and metadata.
  • Preparation: scripts/download/bonn.sh.
  • Access/license: follow the Bonn RGB-D Dynamic Dataset terms.

KITTI Depth

Official: KITTI Depth Prediction | Spec: VideoDepth / kitti, root VideoDepth/kitti, adapter DatasetKitti

KITTI provides outdoor driving frames with projected sparse/dense depth annotations. It stresses long-range metric scale and small vertical baselines. The evaluator decodes KITTI depth PNGs with the standard 1/256 depth scale before applying the selected alignment and depth metrics. 

$BENCHMARK_ROOT/VideoDepth/kitti/
  metadata.json
  <drive_or_split_scene>/
    images/                  # image_path, left-camera RGB frames
    depths/                  # depth_gt_path, projected KITTI GT depth PNGs
    masks/                   # mask_path, optional
  • root_path: $BENCHMARK_ROOT/VideoDepth/kitti/<drive_or_split_scene>.
  • image_path: root_path/images; left-camera RGB frames.
  • depth_gt_path: root_path/depths; evaluator decodes projected KITTI PNG depth with scale 1/256.
  • mask_path: root_path/masks when projected-depth masks are materialized.
  • sparse_gt_path: not used for VideoDepth.
  • Required artifacts: KITTI RGB frames, projected GT depth PNGs, and metadata.
  • Preparation: scripts/download/kitti.sh.
  • Access/license: follow KITTI dataset terms.

ETH3D Pose And Reconstruction

Official: ETH3D | Specs: SfM / eth3d, MVRecon / eth3d; pose adapter DatasetEth3DPose

ETH3D benchmark scenes provide calibrated image sets and sparse or dense geometry depending on the task root. The SfM evaluator reads COLMAP-style GT camera poses and compares predicted sparse models by matched image name. MVRecon evaluation can use depth or geometry artifacts when the canonical GT assets are present; meadow and terrace have no GT mesh, so they are SfM-only (11 MVRecon scenes). Adapters read the undistorted images (canonical_image_root()), not every folder under images/. 

$BENCHMARK_ROOT/SfM/eth3d/
  <scene>/
    images/                  # image_path when canonicalized
    sparse/0/                # preferred sparse_gt_path
    dslr_calibration_undistorted/ or dslr_calibration_jpg/  # fallback sparse_gt_path

$BENCHMARK_ROOT/MVRecon/eth3d/
  metadata.json
  <scene>/
    images/                  # image_path
    depths/                  # depth_gt_path, when depth evaluation is enabled
    masks/                   # mask_path, optional
    sparse/0/                # sparse_gt_path, when pose evaluation is enabled
  • SfM root_path: $BENCHMARK_ROOT/SfM/eth3d/<scene>.
  • SfM image_path: root_path/images when present; image names must match the GT and predicted COLMAP models.
  • SfM sparse_gt_path: first valid COLMAP model among root_path/sparse/0, root_path/dslr_calibration_undistorted, and root_path/dslr_calibration_jpg.
  • MVRecon depth_gt_path: root_path/depths when depth-style MVRecon evaluation is used.
  • mask_path: root_path/masks when materialized.
  • Required artifacts: images, sparse COLMAP GT for pose evaluation, and depths/geometry for depth or reconstruction evaluation.
  • Preparation: scripts/download/eth3d.sh downloads each scene into MVRecon/eth3d, finalize_mvrecon_layout.sh copies its laser-scan depth to depths/ and writes the metadata; SfM/eth3d is a symlink to it.
  • Access/license: follow ETH3D benchmark terms.

DTU Camera Pose, Depth, And Mesh Evaluation

Official: DTU Robot Image Data | Specs: MVRecon / dtu, SfM / dtu; pose adapter DatasetDTUPose

DTU is a calibrated multi-view object-scan benchmark (15 scans). The same scans serve SfM pose evaluation and MVRecon reconstruction, which uses the MVSNet-style ObsMask/Plane filtering in eval_dtu_mesh.py. MVRecon fusion masks each view with its image's alpha channel (the object mask), and scaled ICP refines the fused points against the official laser scan (Points/stl/), starting from the pose-based alignment. 3DGS/dtu is a compatibility symlink to MVRecon/dtu. 

$BENCHMARK_ROOT/MVRecon/dtu/
  <scan>/
    images/                  # image_path
    depths/                  # depth_gt_path, millimetre scale
    mask/                    # object masks
    sparse/0/                # sparse_gt_path (SfM and MVRecon)
  Calibration/  ObsMask/  Points/   # shared DTU evaluation assets
  • root_path: $BENCHMARK_ROOT/MVRecon/dtu/<scan> (SfM resolves SfM/dtu, falling back to 3DGS/dtu).
  • sparse_gt_path: root_path/sparse/0; predictions must export a matching COLMAP model.
  • Geometry sidecars: the shared ObsMask/ and Points/ folders are read by the DTU mesh evaluator.
  • Preparation: scripts/download/dtu.sh downloads the official zips; materializing the canonical layout (scripts/preprocess/fuse_depth_map_dtu.py) is not automated yet.
  • Access/license: follow DTU dataset terms.

Tanks And Temples Pose And Geometry

Official: Tanks and Temples | Specs: SfM / tanks_and_temples, MVRecon / tanks_and_temples; pose adapter DatasetTanksAndTemplesPose

Six real reconstruction scenes (Barn, Caterpillar, Courthouse, Ignatius, Meetingroom, Truck) shared by SfM and MVRecon. MVRecon refines the fused prediction with scaled ICP before scoring it against the GT geometry. 3DGS/tanks_and_temples (the SfM registry path) and SfM/tanks_and_temples are symlinks to MVRecon/tanks_and_temples. 

$BENCHMARK_ROOT/MVRecon/tanks_and_temples/
  <scene>/
    images/                  # image_path
    sparse/0/                # sparse_gt_path (or distorted/sparse/0)
    stereo/                  # geometry evaluator assets
  • root_path: $BENCHMARK_ROOT/MVRecon/tanks_and_temples/<scene>.
  • sparse_gt_path: root_path/sparse/0; image names must match the predicted COLMAP model.
  • Preparation: downloaded through Free View Synthesis's ibr3d_tat.tar.gz repackaging (see spatialarena/download.py).
  • Access/license: follow Tanks and Temples dataset terms.

Image Matching Challenge 2020

Official: Image Matching Challenge 2020 | Spec: SfM / imc, root SfM/imc, adapter DatasetIMC

IMC evaluates sparse reconstruction on internet landmark image collections. The benchmark root stores one canonical scene per landmark with COLMAP-compatible sparse GT. The sparse evaluator matches predicted and GT image names, then computes relative pose and Sim(3)-aligned trajectory metrics. 

$BENCHMARK_ROOT/SfM/imc/
  metadata.json
  <landmark_scene>/
    images/                  # image_path, internet landmark images
    sparse/0/                # sparse_gt_path, GT COLMAP cameras/images
  • root_path: $BENCHMARK_ROOT/SfM/imc/<landmark_scene>.
  • image_path: root_path/images; image names are used to match GT and predicted COLMAP poses.
  • sparse_gt_path: root_path/sparse/0.
  • depth_gt_path and mask_path: not used for IMC sparse-pose evaluation.
  • Required artifacts: image folders and GT sparse/0 COLMAP models.
  • Preparation: scripts/download/imc.sh.
  • Access/license: follow Image Matching Challenge dataset terms.

7Scenes MVRecon And SLAM

Official: 7Scenes | Specs: MVRecon / 7scenes, SLAM / 7scenes; adapters DatasetSevenScenes, DatasetSevenScenesSLAM

7Scenes is an indoor RGB-D benchmark. MVRecon uses the seven whole scenes (every recording of a scene mixed in one folder) and scores fused geometry. SLAM uses the 18 official TestSplit.txt sequences, one case per continuous recording: SLAM/7scenes/<scene>_seq-NN holds relative symlinks into MVRecon/7scenes plus that sequence's own sparse/0, so no frames are duplicated. 7Scenes is not part of the SfM track (it duplicated the old SLAM track). 

$BENCHMARK_ROOT/MVRecon/7scenes/
  metadata.json
  <scene>/
    images/                  # image_path, RGB frames of all recordings
    depths/                  # depth_gt_path, RGB-D GT depth maps (mm)
    sparse/0/                # GT poses of all recordings
$BENCHMARK_ROOT/SLAM/7scenes/
  metadata.json              # 18 sequences, depth_png_scale 1000
  <scene>_seq-NN/
    images/                  # relative symlinks -> MVRecon/7scenes/<scene>/images
    depths/                  # relative symlinks -> MVRecon/7scenes/<scene>/depths
    sparse/0/                # sparse_gt_path: this sequence's poses only
  • MVRecon root_path: $BENCHMARK_ROOT/MVRecon/7scenes/<scene>; images, depths and sparse/0 under it.
  • SLAM root_path: $BENCHMARK_ROOT/SLAM/7scenes/<scene>_seq-NN; sparse_gt_path is its sparse/0.
  • metadata: scene entry from each dataset's metadata.json.
  • Preparation: scripts/download/7scenes.sh (MVRecon), then scripts/preprocess/materialize_7scenes_slam.py (SLAM).
  • Access/license: follow 7Scenes dataset terms.

TUM RGB-D Dynamic Objects (SLAM)

  rgbd_dataset_freiburg{2,3}_<name>/
    images/  depths/  sparse/0/

ScanNet++ Depth And Geometry

Official: ScanNet++ | Evaluator: spatialarena/eval/eval_scannetpp_depth.py

ScanNet++ evaluation is exposed through a dedicated evaluator rather than the default registry tuple. It compares predicted depth maps or generated point clouds against ScanNet++ GT depth/mesh assets. This path is intended for dense indoor reconstruction validation where coordinate-frame handling matters: the evaluator can transform predictions into the ScanNet++ mesh frame and optionally refine registration before scoring. 

<scannetpp_root>/
  <scene>/
    dslr/ or iphone/         # RGB frames and camera metadata, depending protocol
    depths/                  # GT depth maps used by depth comparison
    scans/ or mesh/          # GT mesh/point-cloud assets
    transforms.json or metadata sidecars  # frame/axis transforms for alignment
  • scene root: supplied directly through the ScanNet++ evaluator arguments rather than through the default registry tuple.
  • RGB/camera inputs: used to associate method depth sidecars or predicted points with ScanNet++ frames.
  • GT depths: consumed by depth comparison and point-cloud unprojection checks.
  • GT mesh/scan assets: consumed by geometry comparison after evaluator-specific transform and optional ICP registration.
  • transform sidecars: required to move predicted geometry into the ScanNet++ mesh frame before scoring.
  • Required artifacts: ScanNet++ RGB/depth/mesh GT, method depth sidecars or point-cloud outputs, and scene metadata needed for frame transforms.
  • Preparation: manual ScanNet++ access and local canonicalization; keep paths consistent with the evaluator CLI arguments.
  • Access/license: follow official ScanNet++ terms.

Benchmark Dataset Preparation

Download helpers live under scripts/download/. Some datasets are fully automatic, while DTU, ScanNet, and account-gated datasets may need manual source access before canonicalization. After download, regenerate metadata.json and run the layout verifier so the registry and evaluators see the same scene inventory. 

export PROJECT_ROOT=~/Projects/SpatialArena
export PYTHON=~/anaconda3/envs/si_bench/bin/python
export BENCHMARK_ROOT=$SPATIALARENA_ROOT/benchmarks

# Download benchmark datasets. Submit with sbatch for long downloads.
bash scripts/download/marigold.sh
bash scripts/download/sintel.sh
bash scripts/download/bonn.sh
bash scripts/download/kitti.sh
bash scripts/download/7scenes.sh
bash scripts/download/imc.sh

# DTU has a helper plus manual layout notes.
bash scripts/download/dtu.sh "$BENCHMARK_ROOT/MVRecon/dtu_raw"

# Generate metadata for every benchmark dataset root.
$PYTHON scripts/preprocess/generate_benchmark_metadata.py \
  --benchmark_root "$BENCHMARK_ROOT"

# Verify canonical images/depths/sparse assets.
$PYTHON scripts/preprocess/verify_benchmark_datasets.py \
  --benchmark_root "$BENCHMARK_ROOT" \
  --only_ready

Method Output Contract

Benchmark evaluators expect method outputs under a task/dataset/method/scene layout. New methods should export the same artifacts as the existing inference wrappers in scripts/inference/. 

${EXP_ROOT}/${EXP_NAME}/${TASK}/${DATASET}/${METHOD}/${SCENE}/
  depths/                  # required for MonoDepth, VideoDepth and MVRecon evaluation
    000000.npy             # default adapter output; evaluators also accept png|npz|pfm|dpt for external methods
  sparse/0/                # required for SfM, SLAM and MVRecon evaluation
    cameras.bin|txt
    images.bin|txt
    points3D.bin|txt       # optional for pose metrics, useful for viewers
  pointcloud.ply           # optional dense/sparse viewer artifact
  metrics.json             # optional method-native metrics; verifier can require it when configured

The standard case-list runner writes predictions and immediately verifies and evaluates them. During scoring, adapters write numeric .npy depth maps because metrics need metric depth values. After a case is scored, spatialarena/templates/_engine/run_method_case_list.sh materializes colorized PNG previews under ${REPORT_DIR}/${TASK}/${DATASET}/${SCENE}/depth_visualizations and removes the numeric depth arrays. Set KEEP_DEPTH_VISUALIZATIONS=0 to skip PNG materialization. Prediction folders are temporary by default: after the post-evaluation visualization step, the runner removes the method output directory and keeps verifier/evaluator reports plus PNG visualizations under REPORT_DIR. Set KEEP_PREDICTIONS=1 only when you need to debug or archive non-depth prediction artifacts such as sparse COLMAP outputs. Adapter scratch folders such as _resized_input_images*, _come_raw*, and _cut3r_raw* are removed after a successful export; set KEEP_INTERMEDIATE=1 or pass --keep_intermediate to an adapter when debugging raw method outputs. The runner also refuses EXP_ROOT or REPORT_DIR inside BENCHMARK_ROOT unless ALLOW_BENCHMARK_ROOT_OUTPUT=1 is set for intentional debugging. A case file line has four fields: task|dataset|scene|interval. For example, VideoDepth|sintel|market_2|10 samples every tenth frame from the Sintel scene.

Run Benchmark Scripts

export PROJECT_ROOT=~/Projects/SpatialArena
export PYTHON=~/anaconda3/envs/si_bench/bin/python
export BENCHMARK_ROOT=$SPATIALARENA_ROOT/benchmarks
export BENCHMARK_EVAL_ROOT=$BENCHMARK_ROOT/_evaluation
export EXP_ROOT=$BENCHMARK_EVAL_ROOT/artifacts
ENGINE=spatialarena/templates/_engine

# Each run is a GPU inference job, then a CPU evaluation job with the same arguments.
# A full suite keeps one report folder per method, shared by every run (reruns
# overwrite in place): reports/benchmark_full_reports/full-depth/<METHOD_ID>,
# reports/benchmark_full_pose_reports/full-pose/<METHOD_ID>,
# reports/benchmark_full_slam_reports/full-slam-<range>/<METHOD_ID>.
# Suites: sampled, sparse, monodepth, full-depth, full-pose, full-slam.
JOB=$(sbatch --parsable --export=NIL $ENGINE/run_method_benchmark_infer.sh VGGT_OMEGA full-depth rgb)
sbatch --export=NIL --dependency=afterok:$JOB $ENGINE/run_method_benchmark_eval.sh VGGT_OMEGA full-depth rgb

# SLAM: one range track at a time (short = stride 10, long = stride 3); only the
# track's methods run (python -m spatialarena.slam_protocol methods short).
sbatch --export=NIL,SLAM_RANGE=long $ENGINE/run_method_benchmark_infer.sh PI3_X full-slam rgb

# Validate previously generated predictions without rerunning inference.
$PYTHON scripts/preprocess/verify_prediction_outputs.py \
  --benchmark_root "$BENCHMARK_ROOT" \
  --experiment_root "$EXP_ROOT" \
  --experiment_name benchmark_sampled_VGGT_OMEGA_manual \
  --methods VGGT_OMEGA \
  --tasks VideoDepth MVRecon SfM \
  --strict

Metric Protocols

Depth Metrics

Source: spatialarena/eval/depth_prediction_evaluator.py

Depth evaluation pairs prediction and GT files by normalized frame key, resizes predictions to GT resolution when necessary, applies GT/prediction scale factors, builds a valid mask, aligns prediction depth, optionally clips the aligned prediction, and scores only valid pixels.

\[ \mathcal{V} = \left\{u \mid \operatorname{finite}(d_{gt}(u)) \land \operatorname{finite}(d_{pred}(u)) \land d_{gt}(u) \gt d_{min} \land (d_{max}=\varnothing \lor d_{gt}(u) \lt d_{max}) \land m(u) \right\} \] \[ \hat{d}(u) = s\,d_{pred}(u) + b \]
  • none: \(s=1\), \(b=0\).
  • median: \(s=\operatorname{median}(d_{gt}[\mathcal{V}]) / \operatorname{median}(d_{pred}[\mathcal{V}])\), \(b=0\).
  • least_squares: solve \(\arg\min_{s,b}\sum_{u\in\mathcal{V}}(s\,d_{pred}(u)+b-d_{gt}(u))^2\).
  • standard (default): resolves task-specific defaults -- per-image least squares for MonoDepth, a sequence-level scale+shift LAD fit for VideoDepth, median for MVRecon depth -- plus dataset-specific GT scales and clipping limits. MonoDepth predictions are single-view: the engine sets BENCHMARK_SINGLE_VIEW=1, so multi-view models see each image on its own, and a scene that mixes image sizes runs once per size.
\[ N = |\mathcal{V}|,\qquad e(u)=\hat{d}(u)-d_{gt}(u) \] \[ \begin{aligned} \mathrm{AbsRel} &= \frac{1}{N}\sum_{u\in\mathcal{V}} \frac{|e(u)|}{d_{gt}(u)} \\ \mathrm{SqRel} &= \frac{1}{N}\sum_{u\in\mathcal{V}} \frac{e(u)^2}{d_{gt}(u)} \\ \mathrm{RMSE} &= \sqrt{\frac{1}{N}\sum_{u\in\mathcal{V}} e(u)^2} \\ \mathrm{RMSE}_{log} &= \sqrt{\frac{1}{N}\sum_{u\in\mathcal{V}} \left(\log\hat{d}(u)-\log d_{gt}(u)\right)^2} \\ \mathrm{log10} &= \frac{1}{N}\sum_{u\in\mathcal{V}} \left|\log_{10}\hat{d}(u)-\log_{10}d_{gt}(u)\right| \end{aligned} \] \[ \delta_\tau = \frac{1}{N}\sum_{u\in\mathcal{V}} \mathbf{1}\left[ \max\left(\frac{\hat{d}(u)}{d_{gt}(u)}, \frac{d_{gt}(u)}{\hat{d}(u)}\right) \lt \tau \right], \qquad \tau\in\{1.03,1.25,1.25^2,1.25^3\} \] \[ \mathrm{iRMSE} = \sqrt{\frac{1}{N}\sum_{u\in\mathcal{V}} \left(\frac{1}{\hat{d}(u)}-\frac{1}{d_{gt}(u)}\right)^2} \] \[ r(u)=\log\hat{d}(u)-\log d_{gt}(u),\qquad \mathrm{SILog}=100\sqrt{\operatorname{mean}(r(u)^2)-\operatorname{mean}(r(u))^2} \]

Sparse Pose Metrics

Source: spatialarena/eval/sparse_reconstruction_evaluator.py

Sparse evaluation reads GT and predicted COLMAP models, matches images by filename, evaluates all image pairs or a deterministic capped subset, and reports relative pose errors plus Sim(3)-aligned absolute trajectory errors. COLMAP camera poses are interpreted as OpenCV world-to-camera transforms.

\[ x_{cam} = R x_{world} + t,\qquad C=-R^\top t \] \[ R_{ij}=R_jR_i^\top,\qquad t_{ij}=t_j-R_{ij}t_i \]
\[ \epsilon_R(i,j)= \cos^{-1}\left( \operatorname{clip}\left(\frac{\operatorname{tr}(R_{pred,ij}^{\top}R_{gt,ij})-1}{2},-1,1\right) \right)\frac{180}{\pi} \] \[ \epsilon_t(i,j)= \cos^{-1}\left( \operatorname{clip}\left( \frac{t_{pred,ij}^{\top}t_{gt,ij}}{\|t_{pred,ij}\|\,\|t_{gt,ij}\|}, -1,1 \right) \right)\frac{180}{\pi} \] \[ \epsilon_{axis}(i,j)=\min(\epsilon_t(i,j), 180-\epsilon_t(i,j)) \] \[ \epsilon_{rel}(i,j)=\max(\epsilon_R(i,j),\epsilon_t(i,j)),\qquad \epsilon_{rel,axis}(i,j)=\max(\epsilon_R(i,j),\epsilon_{axis}(i,j)) \]
  • min_baseline: if the GT baseline is below this threshold, translation errors are set to zero for that pair.
  • RRA_at_T: fraction of pairs with rotation_error < T for thresholds such as 5, 15, and 30 degrees.
  • RTA_at_T: fraction of pairs with translation_axis_error < T.
  • AUC_T: area under the recall curve of relative_pose_error from 0 to threshold T, normalized by T.
  • mAA_30: mean threshold accuracy over integer thresholds up to 30 degrees using max(rotation_error, translation_axis_error).
\[ (s^\*,R_s^\*,t_s^\*) = \arg\min_{s,R_s,t_s}\sum_i \left\|sR_sC_{pred,i}+t_s-C_{gt,i}\right\|^2 \] \[ \mathrm{ATE}_i=\left\|s^\*R_s^\*C_{pred,i}+t_s^\*-C_{gt,i}\right\| \] \[ \mathrm{ATE}_{RMSE}=\sqrt{\operatorname{mean}_i(\mathrm{ATE}_i^2)},\quad \mathrm{ATE}_{mean}=\operatorname{mean}_i(\mathrm{ATE}_i),\quad \mathrm{ATE}_{median}=\operatorname{median}_i(\mathrm{ATE}_i),\quad \mathrm{ATE}_{std}=\operatorname{std}_i(\mathrm{ATE}_i) \]

Geometry Metrics

Sources: eval_dtu_mesh.py, eval_tnt_mesh.py, eval_scannetpp_depth.py, utils.py

Mesh and dense-geometry tasks use dataset-specific registration, cropping, and masks before comparing surfaces. After the evaluator brings predicted geometry into the GT frame, accuracy and completeness are nearest-neighbor distances between predicted and GT point sets or sampled surfaces.

\[ P=\{\text{predicted points after alignment}\},\qquad G=\{\text{ground-truth points or sampled GT surface}\} \] \[ \begin{aligned} \mathrm{accuracy} &= \frac{1}{|P|}\sum_{p\in P}\min_{g\in G}\|p-g\| \\ \mathrm{completeness} &= \frac{1}{|G|}\sum_{g\in G}\min_{p\in P}\|g-p\| \\ \mathrm{chamfer} &= \frac{\mathrm{accuracy}+\mathrm{completeness}}{2} \end{aligned} \]
  • DTU: uses DTU scan masks, bounding boxes, and scan-specific point-cloud evaluation.
  • Tanks and Temples: maps the prediction from the COLMAP frame into the laser-scan frame with the official <scene>_trans.txt, crops prediction and GT with the official <scene>.json volume, then refines with scaled ICP.
  • ScanNet++: builds point clouds from depth sidecars when requested and can refine registration with ICP before scoring.

SLAM Trajectory Metrics

Source: spatialarena/eval/slam_trajectory_evaluator.py; protocol: docs/benchmark/slam_protocol.md

A SLAM case is one recording fed whole, in order, at its range track's stride. The predicted camera-to-world poses \(P_i\) are aligned to the ground truth \(G_i\) with one Sim(3) \(S\) from pose_alignment.ransac_irls_align_sim3 (LMedS RANSAC over the GTSAM pose fit, then a robust refit on all frames), for both rgb and rgb_depth. Errors are then computed over every returned frame.

\[ \mathrm{ATE}=\sqrt{\tfrac{1}{N}\textstyle\sum_i \lVert \mathrm{trans}(G_i) - \mathrm{trans}(S P_i)\rVert^2} \] \[ E_i^{\Delta}=\big(G_i^{-1}G_{i+\Delta}\big)^{-1}\big(\hat P_i^{-1}\hat P_{i+\Delta}\big),\qquad \mathrm{drift}=100\,\frac{\sum_i \lVert \mathrm{trans}(E_i^{1\,\mathrm{s}})\rVert}{\sum_i L_i^{1\,\mathrm{s}}}\ \% \]
  • ate_rmse (m): primary; also ate_mean, ate_median.
  • rpe_trans_step/rpe_rot_step, rpe_trans_1s/rpe_rot_1s: RMSE relative pose error over one input frame and over one second; pairs are formed by input-frame index, so skipped frames do not change the offset.
  • drift_pct: 1-second translational RPE divided by the ground-truth path length \(L\) of the same windows (ratio of sums).
  • completeness: fraction of input frames with a returned pose.
  • Reported alongside: ate_rmse_se3 (scale fixed to 1), alignment_scale, alignment_inlier_ratio.
  • Ranking (report summarizer): mean of the ATE and drift ranks per range track and dataset, among methods that ran every sequence.

Report Schema

Depth, sparse and SLAM evaluators return a dictionary with num_scene_results, num_errors, aggregate metrics, per-scene scene_results, and structured errors. Keeping errors inside the report is intentional: batch evaluation can continue across other scenes while still making missing artifacts or invalid files visible to the data manager.

Every scene result also carries runtime, copied from the adapter's metrics.json by prediction_artifacts.read_adapter_runtime: inference_seconds, model_load_seconds, peak_gpu_memory_mib and runtime_scope (after_model_load for instrumented adapters, legacy for older predictions, subprocess_wall for the long-sequence SLAM systems). scripts/test/summarize_benchmark_reports.py aggregates it per method and dataset.
